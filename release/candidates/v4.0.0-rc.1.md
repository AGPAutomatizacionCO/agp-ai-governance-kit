# Candidato propuesto: v4.0.0-rc.1

**Estado:** preparación del RC en revisión; tag y release aún no publicados. No es una versión consumible por la Mesa.

## Propósito

Primera versión candidata del kit con rutas corregidas, consumo normativo por SHA y política formal de releases. Sirve para probar el proceso y detectar incompatibilidades antes de declarar `v4.0.0` estable.

## Requisitos para publicar el candidato

- [ ] PR aprobado con `AGENTS.md`, `README.md`, `CHANGELOG.md`, política y validador.
- [ ] Workflow `release-validation` verde en GitHub.
- [ ] `compatibility.json` generado desde el commit finalmente aprobado, adjuntado al release y comprobado contra el tag.
- [ ] Compatibilidad probada del alcance piloto: esquemas declarados, `agpctl 0.1.0` y contrato `python-api` v1. Otros perfiles no están cubiertos por este RC.
- [ ] Tag `v4.0.0-rc.1` protegido y apuntando al SHA aprobado.
- [ ] Un proyecto piloto real y un caso negativo evaluados con el SHA del candidato, con resultados archivados (mínimo de `RELEASE-POLICY.md`). Un segundo proyecto se exige antes de generalizar el perfil, no para crear el RC de prueba.

## Bloqueos conocidos

- ADR de ejecutor productivo sin aprobar.
- `START-HERE.md` sigue indicando borrador.
- El [PR de candidato #2](https://github.com/AGPAutomatizacionCO/agp-ai-governance-kit/pull/2) ya fue fusionado. El starter tiene perfiles locales parciales; este RC sólo declara el contrato `python-api` v1, no una certificación de su implementación en todos los proyectos.
- Algunos consumidores de la Mesa siguen usando `main`; su migración está en T01.4. No activar el gate formal hasta fijar el SHA publicado.

## Preparación actual

- `release/compatibility.template.json` declara sólo el perfil piloto `python-api` con contrato `profile.agp/v1` y `agpctl 0.1.0` (intervalo `[0.1.0, 0.1.1)`).
- `python -m scripts.build_compatibility --expected-sha <SHA aprobado> --output <ruta>/compatibility.json` genera el adjunto desde HEAD; rechaza otro SHA y cualquier valor `pending`.
- La [aprobación condicional del piloto](https://github.com/AGPAutomatizacionCO/DOCS-IT-GOVERNANCE/issues/8) exige registrar el SHA final y CI verde antes de publicar el tag. No interpretar esa aprobación como autorización de producción.

## Evidencia local de MA-02 (2026-09-30)

- `python -m unittest discover -s tests -q`: 28 pruebas correctas, incluidas ocho pruebas nuevas del pin versión/SHA (tag ligero o anotado, mismatch, tag ausente, fallo de red, YAML duplicado y ref mutable).
- `python scripts/validate_release.py`: correcto. `ruff check --no-cache agpctl scripts tests`: correcto. Se usó un entorno virtual aislado fuera de OneDrive; el caché Ruff dentro del checkout dio `Acceso denegado` y no indica un fallo del código.
- La evidencia local sola **no** sustituye CI remoto, revisión del PR, tag protegido, manifiesto final `compatibility.json` ni prueba de consumo formal desde un proyecto. No completar los valores `pending` por inferencia.
