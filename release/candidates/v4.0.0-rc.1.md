# Candidato propuesto: v4.0.0-rc.1

**Estado:** preparado localmente; tag y release aún no publicados. No es una versión consumible por la Mesa.

## Propósito

Primera versión candidata del kit con rutas corregidas, consumo normativo por SHA y política formal de releases. Sirve para probar el proceso y detectar incompatibilidades antes de declarar `v4.0.0` estable.

## Requisitos para publicar el candidato

- [ ] PR aprobado con `AGENTS.md`, `README.md`, `CHANGELOG.md`, política y validador.
- [ ] Workflow `release-validation` verde en GitHub.
- [ ] SHA del commit aprobado registrado en `compatibility.json`.
- [ ] Compatibilidad real de esquemas, `agpctl` y perfiles declarada sin valores `pending`; si aún no existen, el candidato debe indicar explícitamente que no es consumible por automatizaciones productivas.
- [ ] Tag `v4.0.0-rc.1` protegido y apuntando al SHA aprobado.
- [ ] Un proyecto piloto real y un caso negativo evaluados con el SHA del candidato, con resultados archivados (mínimo de `RELEASE-POLICY.md`). Un segundo proyecto se exige antes de generalizar el perfil, no para crear el RC de prueba.

## Bloqueos conocidos

- ADR de ejecutor productivo sin aprobar.
- `START-HERE.md` sigue indicando borrador.
- `agpctl`, esquemas y pruebas existen en el checkout local, pero aún no se publican en `main` ni se han probado como workflow de GitHub. El starter tiene perfiles locales parciales; no hay compatibilidad de perfil publicada.
- Algunos consumidores de la Mesa siguen usando `main`; su migración está en T01.4.

## Evidencia local de MA-02 (2026-09-30)

- `python -m unittest discover -s tests -q`: 28 pruebas correctas, incluidas ocho pruebas nuevas del pin versión/SHA (tag ligero o anotado, mismatch, tag ausente, fallo de red, YAML duplicado y ref mutable).
- `python scripts/validate_release.py`: correcto. `ruff check --no-cache agpctl scripts tests`: correcto. Se usó un entorno virtual aislado fuera de OneDrive; el caché Ruff dentro del checkout dio `Acceso denegado` y no indica un fallo del código.
- Esta evidencia **no** sustituye CI remoto, revisión del PR, tag protegido, manifiesto final `compatibility.json` ni prueba de consumo desde un proyecto. No completar los valores `pending` por inferencia.

No usar este candidato para autorizar producción.
